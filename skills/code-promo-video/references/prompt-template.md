# 代码宣传片高命中率需求提示词模板

当用户想先输出一份可直接交给代码/视频 Agent 执行的清晰指令时，按下方骨架组织并仅填入从项目材料中核实过的信息：

```markdown
请先通读我们的项目 <项目路径或源码位置>（README、核心前端代码与 <单页/品牌资料>），理解产品与使用场景后，用代码（如 Remotion）为它制作一支 <时长，如 45 秒> 的宣传视频，用于 <核心用途：复赛答辩 / 招新宣发 / 产品发布>。

### 创意与讨论方式
- 请先结合项目真实内容，不要只局限于固定套路：你可以参考 <Apple 宣传片留白质感 / 高燃卡点 Bento> 作为备选基准，但**鼓励额外发掘 1–2 种更贴合本项目的视觉叙事方向**（如需要可先出几个关键帧小样供我对比挑选），确认或混搭后再渲染成片。

### 项目要点与真实数据边界（严禁编造或使用过期信息）
- **产品定位与解决的问题**：<用一两句话概括为谁解决什么卡点>
- **核心机制与痛点应对**：<列出 3–5 条痛点与产品真正实现的闭环>
- **真实演示案例与硬数据（只能使用以下核实数据）**：<列出具体观测数、指标、日期、支持单位等；不要自行补造虚构数字>
- **品牌资产与配色**：主视觉配色 <品牌色系>；真实 Logo / 吉祥物原稿路径在 `<相对品牌素材路径>`。

### 叙事、画面与交互要求
1. **压缩叙事与节奏**：不要逐条慢念长篇痛点；多条痛点可用快闪叠层后收束成一句核心命题，关键画面留足阅读时间。
2. **禁止静态图凑数**：工作台或核心流程请用代码重建真实交互（输入、光标点击、状态流转、结果浮现）；行业/能力展示请做“一秒可辨”的具象微界面，不要堆砌无语义几何圈或空白模板卡片。
3. **音乐与卡点**：使用程序合成音轨或可商用音效，让转场、点击与高潮落版严丝合缝。

### 交付与硬核验收规格
- 规格：`1920×1080`，`<30fps 或 60fps>`，时长准确 `<45 秒>`，导出带 `48kHz` 立体声音轨的 `+faststart` H.264/AAC MP4。
- 交付清单：成品 MP4 + 全阶段关键跃迁帧截图（含操作前后/网格各阶段/叠加安全区）+ 简要设计思路说明。
```
