# 演示发布检查清单

在离演示还有 72 小时以内，或者要推送公开仓库、部署演示服务器之前用。逐项打勾，有一项没过就先不对外。

## 1. 数字只有一个来源
- [ ] 维护一张演示数字表：屏幕、幻灯片、视频、README 里出现的每个数字，都写明出处（文件、查询、运行编号）。
- [ ] 幻灯片、字幕、界面文字都从这张表生成，或者对照这张表核对。
- [ ] 合理的差异要在画面上写明，比如「登记 N 行，删缺失后用 N−1 行」「检索 40 篇，精选 9 篇」。不然评委会以为数字前后矛盾。

## 2. 预生成结果，标明来源
- [ ] 演示案例提前生成好并冻结，现场回放，只留少量现场操作。
- [ ] 每个产出都标明是「预生成」「现场生成」还是「旧版或人工整理」，不能把人工整理的内容说成现场生成。
- [ ] 准备一段录屏，断网或模型挂了的时候用。
- [ ] 不填任何模型密钥，演示也能走通。

## 3. 推送前清理仓库
- [ ] 扫描改动和已跟踪文件里的密钥：key 的格式、`.env*`、token。
- [ ] 内部文档（代理指令、执行计划、SPEC 草稿、进度日志）取消跟踪并加进 gitignore；远端的旧分支和 tag 也要查。
- [ ] 带密钥的数据、数据库、备份压缩包不能进仓库。
- [ ] README 是写给外人看的：这是什么、怎么跑、演示在哪。
- [ ] 给演示用的那个 commit 打 tag。如果已安装 git-finish skill，用它来收尾提交。

## 4. 部署前检查（不要拖到部署当天）
- [ ] 列出主机上已在监听的端口，选一个没人用的；共享主机上的其他服务一律不碰。如果已安装 project-orientation skill，用它来查端口归属。
- [ ] 提前确认云防火墙或安全组：实例属于哪个账号、是哪种实例、谁能登录控制台。由用户自己放行端口，或者提前准备好权限受限的 API 凭据。
- [ ] 公开演示环境不放服务端模型密钥。访客自己填，只存在自己的浏览器里，按请求发送，服务器不保存。
- [ ] 如果只有 HTTP，要提醒用户：密钥是明文传输的。
- [ ] 在服务器上留一份简短的部署说明：路径、服务名、怎么更新、怎么回滚。

## 5. 像访客一样验证，再发链接
- [ ] 从外部网络打开公网地址：首页、一个深层链接、一次 API 请求。
- [ ] 只发一个主网址；要发深层链接，就说明是同一个网站。
- [ ] 报告当前线上的 commit 或 tag。没在外网测过，就不说「能打开」。

## 6. 冻结
- [ ] 冻结之后只修会让演示脚本走不下去的 bug。每次改动都要先打回滚 tag、再合并，然后重新走一遍演示路径。

例子：链接没从外网测过就发出去了，结果端口被安全组挡住，又来回折腾了好几轮。
