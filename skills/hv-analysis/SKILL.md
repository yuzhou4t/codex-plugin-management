# 横纵分析法

沿两个轴研究同一对象：

- 纵轴：它如何从起点演变到当前状态。
- 横轴：在明确的当前时间截面上，它与同类、竞品或替代方案有何差异。
- 交汇：哪些历史选择塑造了今天的位置，未来变化受哪些条件约束。

## 1. 确定研究边界

从用户输入确定研究对象、时间范围、比较对象、关注维度和交付形式。信息足够时直接开始；只有缺失项会实质改变研究路线时才追问。

不要预设报告篇幅、竞品数量、写作风格、作者署名或文件格式。让深度与对象复杂度和用户目标匹配。

## 2. 获取当前证据

涉及可能变化的事实时必须联网核实。优先使用当前可用的 `web.run`：

- `search_query`：发现一手来源和关键线索；
- `open`：读取具体页面；
- `find`：在长页面中定位关键证据。

技术问题优先官方文档、代码仓库和论文；公司或产品优先官方公告、监管文件和直接访谈；用户体验可补充社区讨论，但不要把个别声音写成总体结论。

记录事实发生日期与来源发布日期。区分：

- 已核实事实；
- 来源之间存在冲突的事实；
- 基于证据的推断；
- 无法确认的信息。

不要依赖已废弃的工具名或固定环境路径。

## 3. 纵向分析

围绕因果链组织历史，不写成事件清单：

1. 起源背景、初始问题和关键人物；
2. 重要阶段与转折点；
3. 每个转折点的约束、选择和结果；
4. 路径依赖、被放弃的路线和持续影响；
5. 当前能力或弱点的历史来源。

只展开与研究问题相关的节点。证据不足时标注缺口，不补写故事。

## 4. 横向分析

先定义比较集合和时间截面，再选择能解释用户问题的维度。常见维度包括：

- 核心定位与目标用户；
- 技术或方法路线；
- 功能、性能与使用体验；
- 商业模式、价格和资源投入；
- 生态、分发、社区和切换成本；
- 约束、风险和适用边界。

没有直接竞品时，比较替代方案、上一代方法或可能进入者。避免只看参数；说明每个对象为何走到不同位置。

## 5. 横纵交汇

至少回答：

- 哪些历史决定造成当前差异？
- 今天的优势和短板分别源自什么？
- 竞争者采用了哪些不同路径？
- 哪些趋势是延续，哪些变化可能打破路径依赖？
- 哪些未来判断有证据，哪些只是情景推演？

未来情景必须给出触发条件和反证信号，不把预测写成事实。

## 6. 交付形式

默认直接交付结构清晰的研究结果：

1. 研究对象与结论摘要；
2. 证据边界；
3. 纵向演进；
4. 横向比较；
5. 横纵交汇判断；
6. 不确定性与待核实信息；
7. 来源。

只有用户明确要求文件时才创建 Markdown、文档或其他交付物。只有用户明确要求 PDF 时才调用当前 PDF 工作流生成 PDF；PDF 不是本 Skill 的默认终点。

## 质量检查

- 关键事实有可追踪来源。
- 当前信息标注了核实日期。
- 纵轴包含因果与路径依赖，而不只是年表。
- 横轴的对象和维度与研究目标匹配。
- 事实、推断和预测分开表达。
- 结论能够同时由纵向和横向证据支持。
- 不因追求篇幅而重复或填充内容。
