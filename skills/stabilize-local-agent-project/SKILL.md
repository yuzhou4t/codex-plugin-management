# 约束本地项目操作

把“不给机器和项目制造新问题”置于完成任务之前。先限定范围和资源预算，再检查、修改、清理和验证。

## 强制操作协议

### 1. 先声明边界

开始任何工具操作前：

1. 读取适用的 `AGENTS.md`、README 和仓库状态文档。
2. 确认项目根目录、允许检查的产品目录和本轮任务目标。
3. 运行 `git status --short`，把已有修改和未跟踪文件视为用户资产。
4. 告诉用户本轮只检查哪些路径，以及是否可能触发大量 I/O。

默认禁止：

- 从 `C:\`、`D:\`、`/`、用户主目录或工作盘根目录开始递归扫描；
- 为“找大文件”而遍历整机、全盘哈希或建立全盘索引；
- 在用户目录、系统临时目录或系统盘 AppData 中创建项目 worktree；
- 未设置上限地生成候选目录、日志、会话、备份、截图或构建产物。

如果发现已有整盘扫描或无界任务，立即停止它并向用户说明。

### 2. 先做项目架构与 Git 审查

在改代码前建立最小项目地图：

- 入口、核心模块、客户端、服务端、存储、构建、发布和测试；
- 当前分支、HEAD、远端、submodule/LFS、Git object database；
- 所有 worktree 的路径、分支、状态和是否 `prunable`；
- 源码、用户数据、生成物、缓存、模型/SDK 和发布证据的边界；
- 已实现、默认启用、仅文档声明和已真实验证之间的差异。

不要把 worktree 或候选目录的体积误算为 Git 历史。用 `git count-objects -vH` 和 `git worktree list --porcelain` 分别举证。

### 3. 只做定点存储检查

按以下顺序检查：

1. 文件系统剩余空间；
2. 项目顶层已知目录；
3. 明确的 `.data`、`.tools`、`artifacts`、`build`、cache 和 release 目录；
4. Git 对象与 worktree；
5. 产品已知的运行数据和发布证据目录；
6. 用户明确指定的其他路径。

优先使用浅层枚举和目标目录统计。不要因为第一次结果不完整就扩大到整盘扫描。具体命令与检查项见 [references/storage-git-checklist.md](references/storage-git-checklist.md)。

### 4. 查找无界留存

审查代码和配置是否存在：

- 正文、对话、任务、附件、音频或其他历史的 `unlimited` 生产留存；
- 审计表、日志、备份、重试队列只有追加而没有时间、条数或字节上限；
- 每次构建复制 `.tools`、`node_modules`、Gradle 缓存、SDK、模型；
- worktree 只创建不回收，或失败/取消路径不清理；
- 调度失败后高频重试，持续写磁盘；
- timestamp/commit 命名的临时目录没有启动恢复和清理策略。

要求每类可增长数据至少具备一种硬限制：有限天数、最大条数、最大字节数或最大目录数量。

### 5. 设置变更闸门

以下操作必须先列出精确目标、影响和恢复方式，并取得用户明确确认：

- 递归删除或移动目录；
- 缩短数据留存；
- 清理发布/回滚证据；
- 安装大型 SDK、模型或依赖；
- 创建系统盘 worktree 或改变 Git 历史；
- 执行预计产生大量文件或超过项目磁盘预算的构建。

任何时候都禁止：

- 删除范围不明确的路径；
- 用未解析变量、宽泛 glob 或盘符根目录执行破坏性命令；
- 删除当前源码、活动安装、运行数据库、密钥或用户未确认的内容；
- 为绕过权限或安全策略切换到另一套 shell 拼接删除命令；
- 把凭据、个人正文或本机私有路径提交到 Git。

### 6. 实施持久护栏

用户要求修复时，优先加入：

- 仓库级 `AGENTS.md`：禁止整盘扫描、系统盘 worktree 和候选内复制依赖；
- 快速、只读的存储预检命令，在大构建前失败关闭；
- worktree 的身份校验、干净自动清理、脏结果保留和硬数量上限；
- release candidate、expanded artifact、staging 和备份的保留上限；
- 生产正文有限留存，审计单条大小与总行数上限，日志按时间和字节轮转；
- 失败调度退避和回归测试。

不要仅把无界缓存从一个盘迁到另一个盘。

### 7. 保守清理

只有用户确认后：

1. 用版本、manifest、成功结果和当前运行身份确定保留集合。
2. 默认保留当前源码、活动版本、一个已验证回滚和必要的小型证据。
3. 输出待删除的精确绝对路径和数量。
4. 验证每个目标位于批准根目录内，且不是项目根、盘符根或活动数据目录。
5. 先正确注销 Git worktree，再删除物理目录；处理 Windows 长路径时使用受验证的长路径 API。
6. 清理后复核磁盘空间、保留集合、Git worktree 和存储预检。
7. 明确告诉用户删除了什么、释放多少、是否可恢复。

## 交付格式

最终报告只保留：

- 检查范围与未检查范围；
- 主要占用来源及证据；
- 架构/Git/留存问题；
- 已实施护栏；
- 清理前后空间与保留项；
- 测试结果；
- 尚需用户决定的事项。

不要把与本次项目安全和存储无关的产品路线塞进报告。
