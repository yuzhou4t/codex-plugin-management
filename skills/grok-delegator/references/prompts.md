# Reusable prompts

这些提示词用于在另一台电脑上建立同样的工作流，或在日常对话中直接调用。Skill 已安装时，使用 `$grok-delegator` 或简短的明确指令即可，无需每次重复完整引导词。

## Bootstrap: on-demand Grok delegation

```text
请在当前 Codex 环境中建立“按需委派 Grok”的能力。

只有当我明确说“让 Grok……”“调用 Grok……”或使用 $grok-delegator 时，才把任务交给 Grok。普通任务继续由当前 Codex 模型处理，不自动调用、轮换或替换其他模型，也不自动追加规划或复核角色。

先检查这台电脑实际安装的 Grok CLI 路径、版本、帮助信息和订阅可用性，不要复制另一台电脑的绝对路径。使用已有订阅登录，不切换 API Key，不启用额外付费或自动充值，不修改账户设置。Grok 未安装、未登录、额度不足或网络异常时，报告实际原因；不要假装已经调用，也不要静默改由当前模型完成。

每次委派前，Codex 先检查项目并完成任务合同：唯一 id、任务模式、最小可用工作区、完整目标、写入范围、允许执行的命令、独立检查和可观察的验收标准。在发送前展示这份简明合同。我已经明确要求使用 Grok 时可以直接继续，只有数据范围或外部副作用扩大时才重新询问。

让 Grok 在 workspace 沙盒中运行。聚焦任务使用 allowed_paths；当我要求它像 Codex 一样处理整个项目时，启用 workspace_write，使它可以直接修改最小任务工作区内的普通文件，同时保护 .git、凭据、Codex/Grok 配置和工作区外路径。它可以运行计划中声明的命令，并在合同启用时联网检索。不要使用 bypassPermissions 或 always-approve。

Grok 独立完成整个有界任务：读取、实现或调研、运行检查、修复失败并返回证据。Grok 完成后，Codex 检查实际 changed paths 和 diff，重新运行独立检查；界面任务打开真实页面或应用，调研任务打开重要原始来源。Grok 的文字声明、退出码 0 或文件存在都不能单独作为验收通过。

如果 Codex 发现具体缺陷，把全部有依据的问题合并后交回同一个 Grok 会话。不要静默启动替代会话。同一阻塞经过两次有依据的修复仍存在时停止。最后报告 Grok 实际做了什么、Codex 独立验证了什么、剩余限制，以及是否发生提交、推送、部署或外发。

如果用户的 Skill 仓库已有 grok-delegator，请安装该 Skill；否则只建立项目级等价适配器，在一次性工作区完成真实验证后再声明可用。
```

## Daily research request

```text
让 Grok 调研【主题】。请实际联网搜索并打开原文，把完整报告写入【文件路径】；只允许修改这个文件。报告需要包含【具体要求】、原始来源链接、来源日期、不同来源的分歧、缺失证据，以及已验证事实和推断的明确边界。完成后你再独立打开重要来源复核，并把经过验收的结果返回给我。
```

只要对话答案时，明确写“response-only”并使用空的 `allowed_paths`，不要因为任务类型是调研就自行创建文件。

## Planned engineering execution

```text
使用 $grok-delegator 完成这个任务。先检查仓库，形成具体实施计划和任务合同；计划完成后再让 Grok 独立读取相关代码、完成整个有界修改、运行检查、修复失败并返回回执。对最小相关项目工作区启用 workspace_write，让 Grok 可以直接修改其中的普通项目文件，并允许它运行【命令列表】。独立检查是【检查列表】，可观察结果必须满足【验收标准】。Grok 完成后，你亲自审阅实际 diff 并重跑检查；界面任务打开真实页面或已安装应用。验收失败时，把具体问题合并后交回同一个 Grok 会话修复，再重新验收。
```

## Short engineering request

```text
让 Grok 修复【问题】。工作目录是【目录】；如果是完整工程任务，启用 workspace_write，否则只允许修改【文件或目录列表】。允许运行【命令列表】，验收标准是【标准】。Grok 完成后，请你独立审阅实际 diff、运行【检查】，再向我回传结果。
```

## Permission meaning

“给 Grok 和 Codex 一样的权限”指同样的项目级能力与审批边界：workspace_write 模式下，Grok 可以直接读取和修改任务工作区内的普通文件，并运行任务已授权的命令、测试、构建和联网操作，不重复确认。工作区外路径、受保护配置或凭据、新的外部副作用、发布、部署、破坏性操作和主机级操作交回 Codex 审查；这不等于关闭沙盒或开放整台电脑的无条件权限。
