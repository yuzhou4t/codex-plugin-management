# 情境 → Skill（AO 感知统一表）

权威路由参考：`ask-matt` 与 `architect-led-agent-build` 共用；勿在别处复制维护第二份。

**用法**：先判只读约束、执行者角色、是否 AO 模式，再选一行主流程；纪律 Skill 按步骤附加。触发短语是例子，不是关键词匹配器。允许「无需加载额外 Skill」。

| 情境 | 触发短语示例 | 加载与下一步 | 禁止 |
| --- | --- | --- | --- |
| 只读讨论 / 评审 | 「只评审这个方案，不改文件」 | 必要时 `ask-matt` 选讨论方法；只输出分析 | 自动写 SPEC/ADR/工单，或启动实现与派活 |
| AO 工单执行者 | 「你负责 T3，按任务书实现」 | 仅本票需要的 `tdd` / `diagnosing-bugs` / `pr` 等 | 启动架构师流程、认领他票、`implement-spec`、自行继续派活 |
| 小改，目标清楚 | 「把这个按钮文案改掉」 | 直接做；明确要测试先行时再 `tdd` | 强行 grill→SPEC→拆票，或自动开架构师交付 |
| 思路未清 | 「我有个想法，先帮我问清楚」 | 有仓且允许沉淀：`grill-with-docs`；无仓：`grill-me`；只读则对话澄清 | 因有仓库就自动写词表/ADR；问环境可自查的事实 |
| 多会话 + 明确委派统筹 | 「周五演示，你当架构师，让 Codex 做」 | `architect-led-agent-build`；缺规格用 `to-spec`，缺工单用 `to-tickets`（Grok Bot 用 Skill 工具按名加载）；然后任务书 → `ao spawn` | 用 `implement` / `implement-spec` 接管派活；重复生成已有权威 SPEC |
| 外来 bug / 请求堆积 | 「把用户报来的问题整理成可派工单」 | `triage`；AO 下由架构师决定派发 | 再 triage `to-tickets` 已产出的票；把 `ready-for-agent` 当抢票授权 |
| 难 bug / 间歇 / 性能回归 | 「这个偶发错误一直定位不出来」 | `diagnosing-bugs`；先建能红的反馈环 | 无复现就猜因；借诊断扩大到他票 |
| 大雾，路径看不清 | 「目标很大，关键决策都没理清」 | `wayfinder`；雾散后 `to-spec`；有 deadline 也要限探索范围/时间 | 决策地图直接当实现计划；暗中派研究子代理 |
| 设计需可运行答案 | 「状态流转得跑一下才知道」 | 明确问题后 `prototype`；需委派时经 AO；仅跨目录/harness 才 `handoff` | 原型当正式交付；默认开生产集成 |
| 写 PR 描述 | 「替这个改动写 PR 说明」 | `pr` | 写正文 ≠ 获得创建/推送/合并授权 |
| 迷路 | 「Matt 装了这么多，现在该用哪个？」 | `ask-matt`：识别角色、模式、阻塞，给出**一个**下一步 | 默认完整 idea→ship；一次预载整套；推荐自循环 |

## 假触发 / 双轨 / 抢活（硬规则）

- **假触发**：依据当前请求的意图、角色与允许动作选流程；讨论 Skill、引用示例、存在工作目录或出现 SPEC 等词，不构成执行授权。只读约束覆盖所有文件与 tracker 写入。
- **AO 双轨**：AO 模式下，所有委派（含被加载 Skill 内部的探索/研究/审查代理）统一由架构师经 `ao spawn`；原生子代理与自动领取路径须适配或跳过。AO 不可用时报告派活受阻并继续独立工作。
- **工人抢活**：收到任务书即按执行者角色只做本票；新增任务、跨票决策、额外派活交回架构师。工人不加载 `architect-led-agent-build` 或 `implement-spec`，不自行领取下一票、合并基线或推进 AO 验收。
