# 验收与交付

## 交付前核对

完成指本轮约定的结果已成立。执行者提供实测和交付证据，架构师亲读关键产物与差异，并组织独立复验、复审；不要求用户再说一次“验收通过”。

- 原要求及已接受的变更得到覆盖。从实际交付入口走通主要操作及相关失败场景。页面、后端和局部测试通过后，还要验证它们连接起来的结果。
- 实测、所需检查和复审对应当前交付版本。修复后重新验证受影响部分，旧版本的通过结论不能覆盖新改动。AO 评审先看已有结果；启动成功不代表评审通过。
- 约定的提交、推送、PR 或上线动作确已完成。交到 PR 时核实真实 URL、仓库、分支与当前提交，核对 AO 实际状态；`claim-pr` 只挂接。调研和明确的本地交付按原范围验收，不凑空 PR。
- 影响交付的缺陷已修复并复验。丢稿、串作品、权限泄露、主流程中断不能留给用户发现。可独立处理的小瑕疵按影响分流，不无限追求完善。

完成报告简短说明交付结果、实际验证和复审结论，附真实 PR 与适用的试用入口。合并、部署、安装分别按实际结果报告。日常返修继续做，不把“待验证”“正在修”当最终交付。

## 常见偏差

| 问题 | 处理与确认依据 |
| --- | --- |
| 自报完成、checkpoint 或看板就绪被当成验收 | 回到原要求核对实物与独立结果。执行者不自行 `ao report --done` 或代替架构师宣布验收。 |
| 少量产物、单页、单测、旧预览被说成全部完成 | 只报告已验证范围；补齐主流程、前后端连接和真实入口。批次数量不能替代质量，恢复到 idle 也不代表旧任务完成。 |
| 示例通过，真实依赖缺失 | 区分模拟与真实验证。若原约定以后接入，按该范围交付；本轮必需的外部条件缺失则保留未完成项，说明实际替代验证及最小阻塞，不改写失败事实。 |
| AO 评审故障 | 先修复评审环境，再取得实际结论并处理发现；已有授权允许等价独立评审时，可记录替代原因与结果。平台批准、AO 批准和合并权限分别核对。 |
| 历史任务反复检查却不完成 | 核原要求和后继成果，补完仍有效的缺项。被替代或撤销的任务按 [AO 收尾](AO-OPERATIONS.md#会话收尾) 处理，不能为减少待办而归档未完任务。 |
| 不断往旧任务加新要求 | 先完成本轮明确范围，变更按 [工作流](WORKFLOW.md) 处理。只有明确持续完善授权才在约定边界内继续扩展。 |

真正缺少权限、必要信息或外部条件时，及时说明已完成、未完成和需要用户做什么，继续独立部分。没有完成就如实保留状态；完成标准也不扩大已约定的范围。
