# 保留反馈与维护版本

用户纠正后，把可复用的行为改进写回对应条目，项目范围、监督频率、临时进度和私有信息留在项目记录。优先修正已有规则，合并同义句与冲突，不持续叠加禁令。主入口保持简短，细节按情境查找。

精简或跨宿主同步前，对照维护仓、目标技能库及未同步反馈。保留反馈解决的问题、必要处理方式与判断依据，可以改写和合并；被替代的旧措辞由 Git 历史保留，不在当前正文同时维护互斥规则。不要删掉仍有用的参考入口。

更新后检查引用、元数据和实际场景是否仍能得到原定成果。分别验证仓库版本、安装副本和宿主实际读取结果；复制成功不等于旧对话已经重载。有 `UpdateSkill` 等工具的宿主，先读当前版本再更新相关文件，并重新加载回读。模型无法执行的后台监督或强制约束，不写成已经生效的机制。

## GitHub 同步

沿用用户的维护约定，在本技能提交收尾时评估；这不是后台守护或定时任务。

- 累计 10 个修改本技能路径的有效本地提交后，同步到已核实的对应 GitHub 分支。用户明确要求立即同步时直接同步，不凑提交数。
- 现查远端，以该对应分支上最近一次成功同步本技能的提交为基线。基线为当前分支祖先时可用 `git rev-list --count <基线>..HEAD -- skills/architect-led-agent-build/`；分叉时先比对相关改动，不能套用错误计数。
- 推送前取最新远端并保留其中反馈。只有能安全快进、且差异只含本技能及必要旧路径指针修正时才推对应分支。否则把本技能变更隔离到同步分支并开 PR，合并沿用实际授权。不强推、不改写已推历史、不跳过 hook。
- 核实对应分支已包含成功同步的提交后才更新计数基线。仅推独立分支或开 PR，不代表默认分支已更新。

同步授权仅覆盖本技能和已核实仓库，不扩展到其他项目、技能、合并、部署或权限。汇报说明改动与验证、GitHub 分支和链接，以及各宿主是否实际加载；保留未同步部分的准确状态。
