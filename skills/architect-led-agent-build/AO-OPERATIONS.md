# AO 派发与接续

## 派发

复用当前仓库注册的 AO 项目、已有任务和 PR。项目未注册时按需 `ao project add`。默认经 `ao spawn` 派调研与实现，标题中文可读，显式项目与 [模型参数](MODEL-ROUTING.md)。任务书放执行者实际可读的位置；本机忽略文件不会自动进入新工作树。

启动或恢复后核对会话、目录、分支、模型与有效权限，关联任务和 PR。执行者只做分配范围的实现、自测与授权的提交、推工作分支、开 PR；不自行再委派，不自行 `ao report --done`。实现默认交到真实 PR，明确限定本地或只做调研时沿用限定；PR 许可不扩大为合并或部署许可。

常规操作沿用已有授权，平台强制人类确认仍交用户。`ao project set-config` 可能替换配置，保留无关字段；变更只影响之后的启动，已有会话另查。不要将 workspace-write 或“不弹日常审批”解释成 bypass-permissions 授权。

AO 不可用先定位并恢复，无法恢复就说明派发或可见性受阻并继续独立工作。只有本次已获非 AO 授权才用 CLI 兜底，仍遵守同样的模型、范围和验收要求。

## 看板、PR 与评审

实现任务的看板列由 PR、检查和 AO review 推导，不能手拖成另一套进度。开发中、验证中、评审中反映当前阶段；就绪表示验收通过可合并，不表示已上线；归档表示结束执行，不表示通过。

约定交到 PR 的任务核实真实 PR 与当前提交。先读 `ao review ls`，再按需要触发评审，核对执行会话、run 和结论；已有结果或 `REVIEW_INVALID` 先查版本与归属。交付判断见 [验收](FAIL-ACCEPTANCE.md)，调研不为看板列凑空 PR。

以下操作容易误用，参数以本机 `ao … --help` 为准。

- `session claim-pr` / `spawn --claim-pr` 只关联已有 PR，不创建 PR 或检出分支。先核对负责人和分支，支持时用 `--no-takeover`。
- `ao report` 从当前执行者上下文报进度，checkpoint 不代表验收，也不是手动设列。向指定会话发指令用 `ao send`，不要假定 report 有 `--session`。
- 接续前查最新结果和已处理事件，避免重复派发。AO Chat、独立 Codex 对话和其他宿主用各自支持的机制，并验证接收和实质执行；`send --steer` 仅用于支持它的 AO Chat。
- 非 AO 兜底获准时，Cursor 提示引用任务书文件，返修用明确 chat ID 的 `--resume`，多任务不混用 `--continue`；Codex 用 `exec --json` 和明确会话 resume，调查只读、实现按授权 workspace-write。

## 会话收尾

按项目授权、依赖和交付事实决定，最新明确的保留或暂停要求优先。

- 已验收、无在途依赖且允许结束时，关闭该任务的会话及不再需要的辅助进程，核对实际停止。保留 PR、产物和接续记录；`exit-agent` 本身不证明会话已终止。
- 仍有效的未完成任务继续恢复、补做与验收，idle 或困难不构成归档理由。保留要求存在时不为清内存结束它；需要恢复时用官方 `session restore` 等接口。
- 已被撤销、替代或冲突的旧任务，获得归档授权后记录依据、后继负责人和未尽要求去向，再归档，保留失败事实与成果。隔离任务维持原访问边界，不为整理而重开或读取敏感上下文。
- 只处理本次相关会话和进程。其他旧会话仅在清理范围已获授权且满足完成条件时处理；不批量按名称 kill，不停止整个 daemon，不顺手 cleanup 工作区、数据库或日志，不动仍在使用的服务。只读任务交回收尾事项。

持续监督频率留在项目约定中。执行停滞见 [恢复诊断](FAIL-EXECUTION.md)。
