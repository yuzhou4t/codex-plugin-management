# 执行失败诊断（按需加载）

**谁读**：架构师。读完后开精炼修复工单；工人只收本票范围与验收，不收本文件全文。

**适用问题**：⑨未完不停/错误主动修复；⑩working/accepted 非开工证据；⑪夜间周末不默认停、监督按项目约定持久化。

---

## 通用处置模板

对任一触发都按同一环：

1. **触发条件**（下方各条）
2. **核查**：官方会话状态、最近产物时间、exit/错误原文（仅安全公开信息）、旧 prompt 范围与单写权、是否有在途依赖
3. **授权内处置**：优先原会话官方接口（`ao send` / resume / restore）；核对旧 prompt 仍覆盖本票；不循环无证据重启；不另开一堆重复 worker；不读内部凭据日志、不绕过平台控制
4. **恢复证据**：先记录接票，再核本票的首个实质动作或产物（新分析正文、相关文件变更、有效命令结果、测试退出码或 PR 更新）。ACK 仅证明接票，不能单独证明已恢复执行；「已 send」「状态 working」也不算
5. **何时才需要用户**：凭据、强制审批卡、外部配额/资源确需用户处理、核实指定模型确不可用需更换、或修复需要越出已授权范围时才问；其余独立项继续

## ⑨ 未完成就暂停 / 出错不修

| 项 | 内容 |
| --- | --- |
| **触发** | 票未验收却 idle/exited/archived；或出现错误后只汇报、不修复；或「先停着等指示」而用户已要求做完 |
| **核查** | 验收勾选是否真完成；错误是否可从公开日志/AO 状态安全取得；是否已有同范围在途会话 |
| **处置** | 未完成 → 接续原会话；错误 → 有证据假设 → 小范围修复 → 实动作验证。禁止把「已停止重复重启」当成最终态而不给接续方案 |
| **恢复证据** | 修复后再次出现可验证产出，或阻塞已升级为「需用户」且独立项仍在推进 |
| **才问用户** | 修复需要新权限、密钥、或官方接口无法恢复且需授权另开路径 |

## ⑩ 假开工（working / accepted / 消息已接受）

| 项 | 内容 |
| --- | --- |
| **触发** | 看板 working、消息「已接受」、checkpoint、或「指令已发送」，但约定时限内无新文件/无测试/无 PR 更新 |
| **核查** | 工作树 mtime、预期路径、PR head、会话是否真在跑命令；对比任务书验收点 |
| **处置** | 以产物为准重开监督；同会话追问阻塞并要求落盘证据；仍无产物则按 ⑨ 修复或记录真实阻塞。禁止只续发空指令冒充推进 |
| **恢复证据** | 验收点对应的新产物哈希/路径/命令退出码 |
| **才问用户** | 工人环境缺用户侧审批才能继续时 |

### 场景钩子：启动约数秒 exit 且无 ACK

按 ⑨+⑩：取公开 exit/错误 → 核对 harness/model 是否按 [`MODEL-ROUTING.md`](MODEL-ROUTING.md) → 优先同任务 restore/resume → 一次有证据的修复后核 ACK 及首个实质产出；禁止无新假设地循环 spawn。

### 场景钩子：状态 working 但无新文件

按 ⑩：列预期路径与最近写入；`ao send` 要求报告阻塞与下一步落盘；超时仍无产物则记「假开工」并升级处置，不把 working 写入进度汇报当完成。

## 临时不可达 / 疑似网络波动

| 项 | 内容 |
| --- | --- |
| **触发** | 指定机器或执行通道短暂 unreachable、超时；一两次失败就停止整个任务 |
| **核查** | 保留错误原文，区分临时网络/执行故障与明确拒绝、审批、认证或账号限制；连接列表标识不等于真实命令成功。网络波动只是待验证可能，不直接断言根因 |
| **处置** | 对暂时性故障按项目已约定的重试预算、间隔退避多次尝试；不忙轮询、不无限重发。优先同机器最小只读探针；恢复后先核任务/投递与产物，写操作先查是否已成功，防止重复派票或重复提交。本轮预算耗尽仍保留恢复点、继续独立工作并由既有监督下轮续试，不取消本地工作或宣布全部暂停。明确安全拒绝/审批/认证不适用网络重试；保持原机器和授权路径 |
| **恢复证据** | 实际请求成功及时间、原任务状态、断连前后新增产物；不能只用 connected 或 accepted 声称复工 |
| **才问用户** | 多轮实证表明确需唤醒/连接设备、重新认证或处理平台审批时；短暂波动不反复交还用户 |

## ⑪ 夜间 / 周末默认无人接续

| 项 | 内容 |
| --- | --- |
| **触发** | 因时段把未完成票默认暂停；或 skill/例程写死「仅工作日白天」导致断档；或准备加「全局每 N 分钟」硬编码进本 skill |
| **核查** | 项目/例程约定的监督频率与值班；未完成票列表；是否有「保留会话」指令 |
| **处置** | 未完成票按项目约定持续接续；监督频率写在**项目例程/约定**，**禁止**写入本 skill 全局「每 30 分钟」或「永不收尾」。时段不是停工理由 |
| **恢复证据** | 例程或项目约定已反映持续接续；未完成票有实质接续证据或明确阻塞；监督设置保存不等于实际执行成功 |
| **才问用户** | 用户要求改项目值班策略或资源预算时 |
