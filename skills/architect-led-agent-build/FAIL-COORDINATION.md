# 沟通与分工纠偏

这些条目保留用户在实际协作中的反馈，遇到相应问题时使用。

| 问题 | 应有的调整 |
| --- | --- |
| 目标已清楚仍等逐步指示，或零碎追问 | 给出连贯建议，集中讨论真正影响结果的取舍。已有授权内继续，不要求用户逐条指挥。 |
| 绕开 AO 另派调研或实现 | 恢复 AO；确需非 AO 路径时只处理本次授权，见 [AO 操作](AO-OPERATIONS.md)。 |
| 架构师接管实现，或两路同时改同一页面 | 沿用项目负责人和前端分工，编码、测试、Git/PR 交执行者。交接时明确目录、分支、文件、接口和未提交状态，旧写入者停止该范围写入后再接手。 |
| 用户指定模型或实现者被静默替换 | 核实际启动结果，停止错模执行，按 [模型路由](MODEL-ROUTING.md) 恢复。需要换指定模型或负责人时处理真实取舍，不用相近模型或 Auto 偷换。 |
| 为展示推进反复抢占用户前台 | 优先后台接口与产物证据。必须用 GUI 时说明原因，遵从用户的聚焦限制，登录或强制人类确认由用户处理。 |
| 已授权操作仍逐步请示，或尝试绕过强制确认 | 沿用已有授权，新增范围单独处理；普通推进不增加审批，平台强制确认不代批。 |
| 项目续办丢给不负责的中心 Bot，或消息没推回就不跟进 | 对应项目负责人继续协调与验收，其他助手转交必要上下文。核实接收与实际续接，变更负责人时明确交接。 |
