# 协调失败诊断（按需加载）

**谁读**：架构师。读完后开精炼修复工单或调整编排行为；工人只收本票，不收本文件全文。

**适用问题**：①调研/实现经 AO；②主动带到规格派活；③完整方案集中取舍；④架构师 vs 工人 vs 前端负责人；⑤指定模型/视觉交接不静默替换；⑥静默后台不抢焦；⑦票内已授权继续但不跳强制卡；⑧对应项目 Bot 接续验收。

---

## 通用处置模板

每项依次执行：触发 → 核查 → 授权内处置 → 恢复证据 → 何时才需要用户。只读对应条目；不预加载其它诊断文件。

---

## ① 调研或实现绕开 AO

| 项 | 内容 |
| --- | --- |
| **触发** | 架构师直接调 Codex/Cursor/Cloud 做调研或实现，或用 `implement*` 替代 `ao spawn`，且用户未授权本次非 AO |
| **核查** | 是否已有统筹授权；是否有「本次非 AO」明文；AO daemon/项目是否可用 |
| **处置** | 能恢复 AO 则改经 `ao spawn`；AO 不可用先恢复并标明可见性；**未授权不得 CLI 绕开**（见 [`AO-OPERATIONS.md`](AO-OPERATIONS.md)） |
| **恢复证据** | 会话出现在 AO 看板；任务书与会话 id 对齐 |
| **才问用户** | 必须非 AO 兜底时请求**当次**授权 |

## ② 被动等待逐步指示

| 项 | 内容 |
| --- | --- |
| **触发** | 目标大致清楚却停在解释/准备；或把常规票内步骤拆成请用户逐步确认 |
| **核查** | 未决决策是否真会改变行为；独立部分是否可继续 |
| **处置** | 补齐 SPEC/工单并派活；仅把会改变行为的缺口写成阻塞问题 |
| **恢复证据** | 已有可检查工单与 spawn，或阻塞问题 ≤2–3 个且独立项在推进 |
| **才问用户** | 仅行为性未决决策 |

## ③ 碎片化逐题问

| 项 | 内容 |
| --- | --- |
| **触发** | 连续多轮单点问题，用户需自行拼方案；或方案未给出就要求逐项拍板 |
| **核查** | 是否已有完整草案与有限选项 |
| **处置** | 先交完整方案 + 集中取舍（有限选项）；每轮最多 2–3 个实质问题 |
| **恢复证据** | 用户可对一版方案做取舍，而非回答长问答清单 |
| **才问用户** | 取舍本身 |

## ④ 角色越界 / 多写者冲突

| 项 | 内容 |
| --- | --- |
| **触发** | 架构师越过约定亲自编码/跑实现测试/Git；或两路工人同改一页；或前端视觉未交接就继续旧写入者 |
| **核查** | 文件责任、分支/worktree、是否有前端负责人与指定实现者 |
| **处置** | 架构师回到编排验收；编码/测试/Git/PR 归工人；前端视觉由负责人协调单写者；冲突时停旧写、交交接单 |
| **恢复证据** | 单写权清晰；交接单含树/分支/文件/契约/未提交状态 |
| **才问用户** | 需要改负责人或扩大改动面授权时 |

## ⑤ 指定模型或工具被静默替换

| 项 | 内容 |
| --- | --- |
| **触发** | 用户点名模型/harness/实现者后，实际启动为其它模型，或「相近替代」未询问 |
| **核查** | spawn/Cloud 返回的实际 model；任务书与路由表（[`MODEL-ROUTING.md`](MODEL-ROUTING.md)） |
| **处置** | 停止错模执行并保留记录；核实官方参数后按指定模型恢复。确需换模才问；视觉返工先更新旧 prompt/范围并交接单写权 |
| **恢复证据** | 核对后的实际 model 与用户指定一致 |
| **才问用户** | 指定 id 不可用时 |

## ⑥ 抢焦 GUI / 破坏静默后台

| 项 | 内容 |
| --- | --- |
| **触发** | 为展示「在做」反复抢前台窗口；或无必要的本机 GUI 打扰；用户要求静默后台 + AO 留痕 |
| **核查** | 是否可用 AO/CLI/日志完成同一核验 |
| **处置** | 改后台与 AO 留痕；核验优先非抢焦手段；确需 GUI 聚焦时先说明，并遵守用户的聚焦限制；需要其批准时先批准再操作 |
| **恢复证据** | 推进证据来自 AO/产物，而非「又切到前台」 |
| **才问用户** | 必须用户本机交互才能完成的登录/审批 |

## ⑦ 票内已授权仍逐步请示；或跳过强制卡

| 项 | 内容 |
| --- | --- |
| **触发** | 已授权范围内操作仍每步问用户；或平台强制人类确认被尝试绕过 |
| **核查** | 任务书/用户授权边界；该提示是否为强制卡 |
| **处置** | 授权内继续；强制卡交给用户；不把「日常推进」做成审批流，也不把强制卡当可跳过 |
| **恢复证据** | 独立项持续推进；强制卡有用户处理记录 |
| **才问用户** | 强制卡本身，或超出已授权范围的新动作 |

## ⑧ 错 Bot 接续 / 中心化代收验收

| 项 | 内容 |
| --- | --- |
| **触发** | 把验收/续办统一丢给非负责项目的中心 Bot；或以「消息没自动推回」为由漏接续 |
| **核查** | 哪一个 Bot/编排助手对本项目负责；例程与会话归属 |
| **处置** | **对应项目 Bot** 负责接续与验收；其它助手只转交上下文，不接管验收结论 |
| **恢复证据** | 负责 Bot 有接续动作与验收记录 |
| **才问用户** | 需要改项目负责人时 |
